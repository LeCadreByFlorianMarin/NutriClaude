🎯 Vision & Périmètre

Le problème

Les pères cadres tech avec un enfant en bas âge galèrent à coordonner la nutrition familiale. Chacun a ses objectifs macros, les courses sont un casse-tête du dimanche soir, et les apps de meal planning ne tiennent jamais plus de 2 semaines. C'est le même profil qui n'a plus de temps pour le sport — celui que Le Cadre aide à récupérer 6h par semaine.

La solution

NutriClaude est un système backend qui connecte Claude (IA) à une base de produits alimentaires enrichie (Open Food Facts), des profils nutritionnels individuels, et une liste de courses partagée triée par rayon. L'interface se fait via des iOS Shortcuts et via Claude en conversation (MCP). C'est à la fois un outil perso, un lead magnet pour l'écosystème Le Cadre, et un bonus premium dans Le Cadre Endurance.

Bounded Contexts

🧑 User Profiles
Gestion des comptes, authentification, profils nutritionnels individuels (objectifs macros, calories, restrictions alimentaires).
🍽️ Recipe Management
Création, stockage et recherche de recettes avec ingrédients, portions, et données nutritionnelles calculées.
📦 Product Catalog
Catalogue de produits alimentaires alimenté par Open Food Facts, enrichi avec le mapping rayon personnalisé.
🛒 Grocery List
Liste de courses partagée entre membres du foyer, triée par rayon, avec statuts (à acheter / acheté).

Principe architectural : Supabase est un détail, pas l'architecture. Le modèle de données et le MCP server sont conçus pour être indépendants du provider. Si demain tu migres vers un Postgres auto-hébergé, seul le layer de connexion change.

🗄️ Modèle de Données

Le schéma suit les principes DDD : chaque table est un aggregate ou une value table claire. Les références entre aggregates se font par ID. Le Row-Level Security (RLS) de Supabase assure l'isolation entre foyers.

households — Foyers (unité de partage)SQL
CREATE TABLE households (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name        text NOT NULL,        -- "Famille Marin"
  created_at  timestamptz DEFAULT now()
);

-- RLS: chaque utilisateur ne voit que son foyer
ALTER TABLE households ENABLE ROW LEVEL SECURITY;

Le foyer est l'unité de partage. Toi et ta femme appartenez au même foyer. La liste de courses, les rayons, et les recettes sont partagés au niveau du foyer. Les profils nutritionnels restent individuels.

profiles — Profils nutritionnels individuelsSQL
CREATE TABLE profiles (
  id              uuid PRIMARY KEY REFERENCES auth.users(id),
  household_id    uuid REFERENCES households(id) NOT NULL,
  display_name    text NOT NULL,       -- "Florian"
  daily_calories  int,                    -- 2200
  daily_protein_g int,                    -- 150
  daily_carbs_g   int,                    -- 250
  daily_fat_g     int,                    -- 70
  daily_fiber_g   int,                    -- 30
  restrictions    text[],                 -- {'gluten-free', 'lactose-free'}
  preferences     jsonb DEFAULT '{}',   -- préférences libres
  updated_at      timestamptz DEFAULT now()
);

-- Index pour la lookup par foyer
CREATE INDEX idx_profiles_household ON profiles(household_id);

Chaque membre du foyer a son propre profil avec ses objectifs macros et ses restrictions. Claude utilise ces données pour proposer des recettes adaptées à chacun.

products — Catalogue produits (cache Open Food Facts)SQL
CREATE TABLE products (
  id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  barcode          text UNIQUE,            -- EAN-13 / UPC
  name             text NOT NULL,
  brand            text,
  categories       text[],                  -- tags OFF
  nutriscore       char(1),                  -- A, B, C, D, E
  energy_kcal_100g numeric(7,2),
  protein_100g     numeric(7,2),
  carbs_100g       numeric(7,2),
  fat_100g         numeric(7,2),
  fiber_100g       numeric(7,2),
  salt_100g        numeric(7,2),
  sugar_100g       numeric(7,2),
  saturated_fat_100g numeric(7,2),
  image_url        text,
  off_data         jsonb,                   -- données OFF brutes complètes
  last_synced_at   timestamptz,
  created_at       timestamptz DEFAULT now()
);

-- Full-text search sur le nom
CREATE INDEX idx_products_name_search
  ON products USING gin(to_tsvector('french', name));

Cache local des produits Open Food Facts. Quand un produit est cherché, on vérifie d'abord le cache. Si absent ou périmé (last_synced_at > 30 jours), on requête l'API OFF et on met à jour. Le champ off_data stocke la réponse JSON brute pour ne rien perdre.

aisles & product_aisle_map — Rayons personnalisésSQL
CREATE TABLE aisles (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid REFERENCES households(id) NOT NULL,
  name          text NOT NULL,        -- "Fruits & Légumes"
  sort_order    int NOT NULL,          -- ordre dans le magasin
  icon          text,                     -- emoji optionnel "🥬"
  UNIQUE(household_id, name)
);

CREATE TABLE product_aisle_map (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id  uuid REFERENCES households(id) NOT NULL,
  product_id    uuid REFERENCES products(id),
  keyword       text,                     -- "poulet" (matching souple)
  aisle_id      uuid REFERENCES aisles(id) NOT NULL,
  -- Soit product_id soit keyword doit être rempli
  CHECK (product_id IS NOT NULL OR keyword IS NOT NULL)
);

-- Index pour le matching par keyword
CREATE INDEX idx_aisle_map_keyword
  ON product_aisle_map USING gin(to_tsvector('french', keyword));

Deux mécanismes de mapping : par product_id (lien exact avec un produit du catalogue) ou par keyword (matching souple — "poulet" → Boucherie, "pâtes" → Épicerie Sèche). Le keyword permet de classer automatiquement des ingrédients même s'ils n'ont pas encore de fiche produit. L'ordre (sort_order) reflète le parcours physique dans ton supermarché.

recipes & recipe_ingredients — RecettesSQL
CREATE TABLE recipes (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id    uuid REFERENCES households(id) NOT NULL,
  title           text NOT NULL,
  description     text,
  instructions    text,                  -- étapes en markdown
  servings        int DEFAULT 2,
  prep_time_min   int,
  cook_time_min   int,
  tags            text[],                 -- {'rapide', 'batch-cooking', 'végé'}
  total_kcal      numeric(8,2),           -- calculé depuis ingrédients
  total_protein_g numeric(7,2),
  total_carbs_g   numeric(7,2),
  total_fat_g     numeric(7,2),
  source          text DEFAULT 'claude',  -- 'claude', 'manual', 'import'
  created_by      uuid REFERENCES auth.users(id),
  created_at      timestamptz DEFAULT now()
);

CREATE TABLE recipe_ingredients (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  recipe_id     uuid REFERENCES recipes(id) ON DELETE CASCADE,
  product_id    uuid REFERENCES products(id),  -- nullable si pas matché
  name          text NOT NULL,        -- "filet de poulet"
  quantity      numeric(8,2),
  unit          text,                     -- 'g', 'ml', 'pièce', 'cs', 'cc'
  aisle_keyword text,                     -- pour le tri rayon si pas de product_id
  optional      boolean DEFAULT false,
  sort_order    int
);

Les recettes sont liées au foyer. Les macros totaux sont calculés automatiquement via une Edge Function qui somme les nutriments des ingrédients matchés. L'aisle_keyword sur chaque ingrédient permet le tri par rayon même sans fiche produit.

grocery_list_items — Liste de courses partagéeSQL
CREATE TABLE grocery_list_items (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  household_id   uuid REFERENCES households(id) NOT NULL,
  name           text NOT NULL,       -- "Filet de poulet"
  quantity       numeric(8,2),
  unit           text,
  product_id     uuid REFERENCES products(id),
  aisle_id       uuid REFERENCES aisles(id),
  recipe_id      uuid REFERENCES recipes(id),  -- d'où vient cet item
  added_by       uuid REFERENCES auth.users(id),
  status         text DEFAULT 'pending',    -- 'pending' | 'bought'
  created_at     timestamptz DEFAULT now()
);

-- Index pour l'affichage trié par rayon
CREATE INDEX idx_grocery_household_aisle
  ON grocery_list_items(household_id, aisle_id);

-- Vue pour la liste triée par rayon
CREATE VIEW grocery_list_by_aisle AS
SELECT
  g.*,
  a.name AS aisle_name,
  a.icon AS aisle_icon,
  a.sort_order AS aisle_sort
FROM grocery_list_items g
LEFT JOIN aisles a ON g.aisle_id = a.id
WHERE g.status = 'pending'
ORDER BY a.sort_order, g.name;

La vue grocery_list_by_aisle est le point d'entrée principal pour les Shortcuts. Elle retourne la liste triée par rayon avec les icônes, prête à afficher. Le champ recipe_id permet de savoir d'où vient chaque item ("ces oignons viennent de la recette Poulet Basquaise").

🔌 MCP Server

Le MCP server est la pièce maîtresse qui connecte Claude à ta base de données. Quand tu discutes de nutrition avec Claude, il peut lire tes profils, chercher des produits, créer des recettes, et alimenter ta liste de courses — directement en conversation.

Tools exposés

ToolDescriptionParamètres
get_profiles Récupère les profils nutritionnels du foyer household_id
update_profile Met à jour les objectifs macros d'un profil profile_id, daily_calories, protein_g, ...
search_product Cherche dans le cache local puis Open Food Facts query ou barcode
create_recipe Crée une recette avec ses ingrédients + calcule les macros title, ingredients[], instructions, servings
list_recipes Liste les recettes du foyer, filtrables par tag household_id, tags?, search?
add_to_grocery_list Ajoute des items à la liste, auto-assignés au bon rayon items[], recipe_id?

Squelette MCP Server

src/index.ts — Point d'entrée MCPTypeScript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { createClient } from "@supabase/supabase-js";

const supabase = createClient(
  process.env.SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_KEY!
);

const server = new Server({
  name: "nutriclaude",
  version: "1.0.0",
}, {
  capabilities: { tools: {} }
});

// Tool: search_product
// 1. Cherche dans le cache local (full-text search)
// 2. Si pas trouvé → appel Open Food Facts API
// 3. Cache le résultat dans products
// 4. Retourne nom + macros + nutriscore

// Tool: create_recipe
// 1. Insère la recette
// 2. Pour chaque ingrédient :
//    - Match avec un produit (search_product)
//    - Détermine le rayon (product_aisle_map)
// 3. Calcule les macros totaux
// 4. Retourne la recette complète

// Tool: add_to_grocery_list
// 1. Pour chaque item :
//    - Résout le rayon via keyword matching
//    - Agrège si l'item existe déjà (additionne qty)
// 2. Insère dans grocery_list_items

async function main() {
  const transport = new StdioServerTransport();
  await server.connect(transport);
}

main();

🌍 Intégration Open Food Facts

API v2
Base URL : https://world.openfoodfacts.org/api/v2

Endpoints :
— /product/{barcode}.json
— /search?fields=...
— /taxonomy?tagtype=categories
Données disponibles
3M+ produits avec :
— Nom, marque, code-barres
— Nutri-Score (A→E)
— Macros pour 100g et par portion
— Ingrédients, allergènes, additifs
— Catégories et labels
Stratégie de cache
Cache-aside pattern :
1. Cherche dans products local
2. Si absent ou > 30 jours → appel OFF
3. Upsert dans products
4. Retourne du cache

User-Agent : requis par OFF
Exemple d'appel Open Food FactsTypeScript
async function fetchFromOpenFoodFacts(barcode: string) {
  const url = `https://world.openfoodfacts.org/api/v2/product/${barcode}.json`;
  const fields = [
    "product_name", "brands", "nutriscore_grade",
    "nutriments", "categories_tags", "image_url",
    "allergens_tags", "ingredients_text_fr"
  ].join(",");

  const res = await fetch(`${url}?fields=${fields}`, {
    headers: {
      "User-Agent": "NutriClaude/1.0 (contact@nutriclaude.com)"
    }
  });

  const data = await res.json();

  if (data.status === 1) {
    return {
      name: data.product.product_name,
      brand: data.product.brands,
      nutriscore: data.product.nutriscore_grade,
      energy_kcal_100g: data.product.nutriments["energy-kcal_100g"],
      protein_100g: data.product.nutriments.proteins_100g,
      carbs_100g: data.product.nutriments.carbohydrates_100g,
      fat_100g: data.product.nutriments.fat_100g,
      fiber_100g: data.product.nutriments.fiber_100g,
    };
  }
  return null;
}

📱 iOS Shortcuts

Quatre Shortcuts couvrent les interactions quotidiennes. Chacun est un workflow Shortcuts qui fait des appels HTTP à l'API REST Supabase.

🗣️ Ajouter un item (vocal)
"Dis Siri, ajoute du poulet à la liste"

1. Dictée → texte
2. POST vers Edge Function
3. L'Edge Function match le rayon via keyword
4. Insère dans grocery_list_items
5. Notification de confirmation
📋 Voir la liste par rayon
"Dis Siri, ma liste de courses"

1. GET sur grocery_list_by_aisle (vue SQL)
2. Groupe par rayon avec l'emoji
3. Affiche dans un menu Shortcuts
4. Tap pour marquer "acheté"
5. PATCH le statut → 'bought'
📸 Scanner un produit
"Dis Siri, scan produit"

1. Ouvre la caméra → scan code-barres
2. GET /products?barcode=eq.{code}
3. Si pas en cache → fetch OFF
4. Affiche nom + macros + Nutri-Score
5. Option "Ajouter à la liste"
🍳 Générer une recette
"Dis Siri, recette pour ce soir"

1. Dicte une idée ou contrainte
2. POST vers Edge Function → appel Claude API
3. Claude reçoit les profils nutritionnels
4. Génère recette + ingrédients JSON
5. Sauvegarde recette + push vers liste

Authentification dans les Shortcuts

Chaque Shortcut stocke un token API (Supabase anon key + JWT utilisateur) dans un dictionnaire Shortcuts persistant. Le JWT est obtenu une seule fois via un Shortcut "Login" qui fait un appel POST /auth/v1/magiclink. Le token est ensuite passé en header Authorization: Bearer {jwt} à chaque appel.

⚡ API Design

Edge Functions (logique custom)

Supabase fournit une API REST auto-générée pour le CRUD simple. Pour la logique métier (matching rayon, calcul macros, appel Claude), on utilise des Edge Functions (Deno).

EndpointMéthodeDescription
/functions/v1/add-grocery-itemPOSTAjoute un item, résout le rayon par keyword matching, agrège les doublons
/functions/v1/generate-recipePOSTAppelle Claude API avec les profils, retourne recette + pousse ingrédients en liste
/functions/v1/sync-productPOSTCherche un produit, cache-aside avec Open Food Facts
/functions/v1/clear-grocery-listPOSTArchive les items 'bought', reset la liste pour la prochaine session
/functions/v1/weekly-menuPOSTGénère un menu semaine via Claude, crée les recettes, pousse la liste complète
